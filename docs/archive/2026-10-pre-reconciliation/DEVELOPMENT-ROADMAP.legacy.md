# 🛠️ نقشهٔ راه توسعهٔ نرم‌افزار OpenEdu Git

> **وضعیت:** پیش‌نویس اولیه – زنده و در حال تکامل  
> **مخاطب:** تیم فنی (برنامه‌نویسان بک‌اند، فرانت‌اند، DevOps)  
> **هدف:** ساخت گام‌به‌گام پلتفرم از MVP تا نسخهٔ کامل، هم‌سو با نقشهٔ راه کلی پروژه.

---

## 🧭 فاز ۰ – پی‌ریزی فنی (هفته ۱ تا ۴)

**هدف:** آماده‌سازی محیط توسعه، مخازن، CI/CD و تصمیم‌گیری نهایی دربارهٔ پشتهٔ فناوری.

### ۰.۱ محیط توسعه و ابزارها

- [ ] راه‌اندازی `docker-compose.yml` با سرویس‌های:
  - PostgreSQL 16 + pg_trgm
  - MinIO (ذخیره‌سازی فایل)
  - Redis (برای کش / صف‌های آینده)
- [ ] افزودن پوشهٔ `backend/` با ساختار اولیهٔ FastAPI
- [ ] افزودن پوشهٔ `frontend/` با پروژهٔ Next.js + TypeScript + Tailwind
- [ ] تنظیم `.editorconfig` و `pre-commit` hooks (linting با ruff, prettier)
- [ ] مستندسازی راه‌اندازی در `DEVELOPMENT.md`

### ۰.۲ CI/CD و استقرار اولیه

- [ ] GitHub Actions: اجرای خودکار تست‌ها و lint روی هر PR
- [ ] استقرار خودکار شاخهٔ `main` روی یک VPS ایرانی (ArvanCloud / Asiatech) یا پلتفرم ابری
- [ ] تنظیم دامنهٔ موقت و SSL

### ۰.۳ تصمیم‌های نهایی پشته

- [ ] تأیید PostgreSQL (با JSONB) به عنوان پایگاه دادهٔ اصلی
- [ ] انتخاب کتابخانهٔ مدیریت مهاجرت: Alembic
- [ ] انتخاب ORM: SQLAlchemy 2.0 (async) یا Prisma برای TypeScript (اگر Node.js انتخاب شود) – اینجا ما FastAPI داریم، پس SQLAlchemy + asyncpg
- [ ] انتخاب ابزار مستندسازی API: Swagger (توکار FastAPI)
- [ ] تأیید MinIO برای فایل‌ها و برنامهٔ آتی Elasticsearch برای جستجوی پیشرفته

## 📚 فاز ۱ – کتابخانهٔ جزوه‌ها (MVP) | ماه ۱ تا ۳

**هدف:** راه‌اندازی نسخه‌ای که در آن کاربران بتوانند جزوه آپلود کنند، جستجو کنند، نظر بدهند و فورک/ادغام انجام دهند.

### ۱.۱ اسپرینت ۱: احراز هویت و پروفایل کاربر (هفته ۱-۲)

**بک‌اند:**

- [ ] مدل `User` (`id, email, password_hash, full_name, title, bio, avatar_url, created_at`)
- [ ] ثبت‌نام/ورود با ایمیل و رمز عبور (JWT access + refresh token)
- [ ] ورود با گوگل (OAuth2) – اختیاری در MVP
- [ ] API های:
  - `POST /auth/register`
  - `POST /auth/login`
  - `POST /auth/refresh`
  - `GET /users/me`
  - `PATCH /users/me`
- [ ] میدلور احراز هویت برای محافظت از مسیرها

**فرانت‌اند:**

- [ ] صفحات: `/login`, `/register`
- [ ] کامپوننت‌های فرم با اعتبارسنجی (react-hook-form + zod)
- [ ] ذخیرهٔ token در httpOnly cookie (با مدیریت سمت سرور Next.js)
- [ ] صفحهٔ پروفایل کاربر (`/profile`) با قابلیت ویرایش

### ۱.۲ اسپرینت ۲: آپلود و نمایش جزوه (هفته ۳-۴)

**بک‌اند:**

- [ ] مدل `Pamphlet` (`id, title, author_id, grade, subject, chapter, method, difficulty, status, created_at, updated_at`)
- [ ] مدل `PamphletVersion` (`id, pamphlet_id, version_number, file_path, file_type, created_by, created_at`)
- [ ] آپلود فایل به MinIO از طریق `POST /pamphlets` (multipart)
- [ ] ذخیرهٔ متادیتا و نسخهٔ اولیه
- [ ] API های:
  - `POST /pamphlets` (ایجاد جزوه + نسخه)
  - `GET /pamphlets/{id}` (جزئیات + لیست نسخه‌ها)
  - `GET /pamphlets` (لیست با pagination و فیلتر)
  - `PUT /pamphlets/{id}/metadata` (ویرایش متادیتا، فقط نویسنده)
  - `GET /pamphlets/{id}/versions/{version_id}/file` (دانلود فایل)

**فرانت‌اند:**

- [ ] صفحهٔ آپلود جزوه (`/upload`) با فرم چندمرحله‌ای:
  - انتخاب فایل (PDF, Word, Markdown)
  - انتخاب متادیتا (پایه، درس، فصل، نوع، سطح)
  - پیش‌نمایش و ثبت
- [ ] صفحهٔ جزوه (`/pamphlets/[id]`) شامل:
  - نمایش PDF با `react-pdf`
  - نمایش Markdown (در صورت نیاز)
  - متادیتا، نام نویسنده و لینک به پروفایل
  - لیست نسخه‌ها (تاریخچه)

### ۱.۳ اسپرینت ۳: جستجو و فیلتر (هفته ۵-۶)

**بک‌اند:**

- [ ] ایجاد ایندکس `tsvector` روی فیلدهای `title` و احتمالاً محتوای متنی جزوه (در صورت ذخیرهٔ متن)
- [ ] ایندکس `pg_trgm` برای جستجوی تقریبی (fuzzy)
- [ ] API `GET /search?q=...&grade=...&subject=...&method=...`
- [ ] پیاده‌سازی pagination با cursor-based
- [ ] (در این فاز Elasticsearch را پیاده‌سازی نمی‌کنیم، اما جایگزینی آن در آینده را آسان می‌سازیم)

**فرانت‌اند:**

- [ ] صفحهٔ اصلی (`/`) با نوار جستجوی برجسته و دسته‌بندی‌ها
- [ ] نتایج جستجو با کارت‌های جزوه، فیلترهای کناری
- [ ] پیشنهادات جستجو (autocomplete) با debounce

### ۱.۴ اسپرینت ۴: همکاری – فورک و پیشنهاد ادغام (هفته ۷-۸)

**بک‌اند:**

- [ ] مدل `PamphletFork` (`id, original_pamphlet_id, forked_by, new_pamphlet_id, created_at`)
- [ ] مدل `MergeRequest` (`id, source_pamphlet_id, target_pamphlet_id, status, created_by, reviewed_by, created_at`)
- [ ] API:
  - `POST /pamphlets/{id}/fork` (ایجاد یک کپی از جزوه به نام کاربر جدید)
  - `POST /pamphlets/{id}/merge-requests` (درخواست ادغام از جزوهٔ فورک‌شده به اصل)
  - `GET /pamphlets/{id}/merge-requests`
  - `POST /merge-requests/{id}/approve` / `reject` (توسط نویسندهٔ اصلی یا داوران)
- [ ] پس از تأیید، نسخهٔ جدیدی روی جزوهٔ اصلی با محتوای ادغامی اضافه شود.

**فرانت‌اند:**

- [ ] دکمهٔ «کپی و بهبود» روی صفحهٔ جزوه
- [ ] صفحهٔ درخواست ادغام با نمایش تفاوت‌ها (diff) – نسخهٔ ساده: نمایش دو نام فایل و توضیحات
- [ ] اعلان‌های درون‌برنامه‌ای برای درخواست‌ها و تأیید/رد

### ۱.۵ اسپرینت ۵: نظرات و امتیازدهی (هفته ۹-۱۰)

**بک‌اند:**

- [ ] مدل `Review` (`id, pamphlet_id, user_id, rating (1-5), comment, created_at`)
- [ ] API:
  - `POST /pamphlets/{id}/reviews`
  - `GET /pamphlets/{id}/reviews`
  - میانگین امتیاز در پاسخ‌های جزوه لحاظ شود.
- [ ] قابلیت «مفید بود / نبود» روی نظرات.

**فرانت‌اند:**

- [ ] ستاره‌های امتیازدهی، بخش نظرات، امکان رأی به مفید بودن کامنت

### ۱.۶ اسپرینت ۶: تست، رفع اشکال و انتشار MVP (هفته ۱۱-۱۲)

- [ ] نوشتن تست‌های واحد و یکپارچه برای API های اصلی (pytest, React Testing Library)
- [ ] تست نفوذپذیری ساده (OWASP ZAP)
- [ ] رفع اشکالات UI/UX بر اساس بازخورد اولیه
- [ ] تنظیم دامنهٔ نهایی و استقرار عمومی
- [ ] انتشار عمومی MVP و جشن 🎉

## 👨‍🏫 فاز ۲ – کلاس‌های آنلاین و فروش دوره‌های ویدیویی | ماه ۴ تا ۶

**هدف:** افزودن قابلیت رزرو و برگزاری کلاس آنلاین، پرداخت ریالی، و فروش دوره‌های ویدیویی.

### ۲.۱ اسپرینت ۷: زیرساخت پرداخت و کیف پول (هفته ۱۳-۱۴)

- [ ] انتخاب درگاه پرداخت (زرین‌پال) و پیاده‌سازی وب‌هوک
- [ ] مدل `Wallet`, `Transaction`
- [ ] کیف پول کاربر (افزایش موجودی با پرداخت آنلاین، برداشت برای معلم پس از تسویه)
- [ ] API:
  - `POST /payments/request` (دریافت لینک پرداخت)
  - `POST /payments/verify` (وب‌هوک)
  - `GET /wallet/balance`, `GET /wallet/transactions`

### ۲.۲ اسپرینت ۸: رزرو کلاس و تقویم (هفته ۱۵-۱۶)

- [ ] معلم زمان‌های حضور (slots) و نرخ هر جلسه را در پروفایل خود تنظیم کند.
- [ ] مدل `ClassSession` (`id, teacher_id, student_id, start_time, end_time, status, meeting_link`)
- [ ] فرایند رزرو:
  - دانش‌آموز یک اسلات را انتخاب و مبلغ را از کیف پول پرداخت می‌کند.
  - وضعیت جلسه `booked` می‌شود.
  - لینک اتاق مجازی تولید می‌شود.
- [ ] اعلان‌ها برای تأیید، شروع جلسه و یادآوری.

### ۲.۳ اسپرینت ۹: کلاس مجازی (WebRTC) (هفته ۱۷-۱۹)

- [ ] ادغام Jitsi Meet (متن‌باز) یا راه‌اندازی سرور LiveKit (سبک‌تر) برای تماس تصویری.
- [ ] ویژگی‌ها: تختهٔ سفید (با ادغام Excalidraw یا tldraw)، اشتراک صفحه، چت متنی، ضبط خودکار.
- [ ] API:
  - `POST /sessions/{id}/join` (برمی‌گرداند توکن اتصال)
  - `POST /sessions/{id}/end` (فقط معلم یا سیستم)
- [ ] ذخیرهٔ ضبط جلسه در MinIO و افزودن به «دوره‌های ضبط‌شده» (اختیاری، با اجازه).
- [ ] مدیریت قطعی و تلاش مجدد.

### ۲.۴ اسپرینت ۱۰: فروشگاه دوره‌های ویدیویی (هفته ۲۰-۲۲)

- [ ] مدل `VideoCourse` (شامل چندین `VideoLesson`)
- [ ] آپلود ویدیو (ترجیحاً از طریق یک CDN داخلی مانند ArvanCloud با آپلود مستقیم امن)
- [ ] ترانسکدینگ خودکار (با استفاده از سرویس ابری یا ffmpeg سروری)
- [ ] صفحهٔ دوره، خرید، دسترسی به ویدیوها
- [ ] محافظت از لینک دانلود (Signed URLs)
- [ ] پیاده‌سازی کمیسیون خودکار (۲۰٪) هنگام خرید دوره

### ۲.۵ اسپرینت ۱۱: ادغام و تست (هفته ۲۳-۲۴)

- [ ] تست کامل گردش کار (رزرو ← کلاس ← پرداخت)
- [ ] بهبود UX و رفع باگ
- [ ] انتشار رسمی فاز ۲

## 🧩 نکات فنی مقطعی در تمام فازها

- **امنیت:** هش کردن رمزها (bcrypt)، rate limiting، CORS، CSP، جلوگیری از XSS/CSRF
- **مانیتورینگ:** Sentry برای خطاها، Prometheus + Grafana برای سلامت سرور
- **نسخه‌بندی API:** پیشوند `/api/v1/`
- **تست:** پوشش حداقل ۸۰٪ برای بک‌اند، تست‌های E2E با Playwright برای جریان‌های اصلی
- **مستندات:** Swagger خودکار + مستندات فرانت‌اند با Storybook (در صورت نیاز)
- **بین‌المللی‌سازی (i18n):** فعلاً فارسی سخت‌کد، اما ساختار آماده برای افزودن زبان‌های دیگر
- **پشتیبانی از RTL:** همیشه در طراحی فرانت‌اند لحاظ شود.
